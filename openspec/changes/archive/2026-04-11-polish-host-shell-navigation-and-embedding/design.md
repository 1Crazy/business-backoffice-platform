## Context

当前主应用已经承担 OA 与 SCRM 的统一导航与内容承载职责，但仍保留了部分实现期的过渡痕迹。第一类问题出现在主应用桌面侧边导航，父级菜单除了“协同事务”“经营管理”等业务语义标签外，还额外挂了域前缀徽标，导致用户扫读时会先看到技术域标识而不是业务分组。第二类问题出现在 `qiankun` 承载路径，宿主内容区与微应用包装层同时按视口高度扩张时，会在业务内容本身未超出可用区域的情况下生成一层空滚动。

## Goals / Non-Goals

**Goals:**
- 让主应用父级导航以业务语义标签作为唯一主文案。
- 让主系统承载子应用时优先继承宿主内容区可用高度，避免空滚动。
- 收敛三套后台侧边导航的滚动反馈，使其默认隐藏、交互时再出现。

**Non-Goals:**
- 不调整 OA、SCRM 业务页面本身的信息架构或卡片排版。
- 不修改任何账号、种子数据或演示人员信息。
- 不重做主应用整体视觉主题，只修正已暴露的壳层行为问题。

## Decisions

### 1. 主应用父级导航直接显示业务语义标签
保留 `协同事务`、`经营管理` 作为分组主文案，并移除父级项前置域徽标。当前业务域仍通过当前激活分组、页面标题区与内容路由前缀表达，不再额外依赖 `OA`、`S` 之类的符号提示。

### 2. 微应用挂载容器继承宿主内容区高度
主应用的 `MicroAppPage` 不再使用基于视口高度的硬编码估算，而是让 `micro-shell`、`micro-stage`、`micro-slot` 继承宿主内容区高度。同时针对 `qiankun` 注入的包装层与 `#app` 根节点追加约束，避免包装层被默认样式拉到整屏高度。

### 3. 子应用根节点只在独立运行时保持整屏最小高度
`oa-web` 与 `scrm-web` 的根节点在宿主模式下恢复自然高度，仅在独立运行模式下保留 `100dvh` 级别的最小高度。这可以避免嵌入态把宿主滚动容器错误撑大，同时不破坏单独访问子应用时的完整壳层体验。

### 4. 侧边导航滚动反馈默认隐藏，仅在交互时显露
三套后台侧边导航统一使用“默认隐藏、悬停或键盘聚焦时显露”的滚动反馈策略。这样既能减少视觉噪音，也能通过 `:focus-within` 保持键盘用户可发现性。

## Risks / Trade-offs

- [Risk] 宿主内容区完全继承高度后，若子应用某页确实超过一屏，可能更依赖宿主滚动容器的真实溢出行为。 → Mitigation：通过浏览器实测同时验证“内容未超出时无空滚动”和“内容超出时仍可正常滚动”。
- [Risk] 隐藏滚动条可能降低部分用户对可滚动区域的直觉判断。 → Mitigation：保留悬停与键盘聚焦显露逻辑，而不是永久隐藏。
- [Risk] 主应用去掉域徽标后，可能被误解为域上下文被弱化。 → Mitigation：继续通过当前分组展开态、标题区 kicker 与路由前缀保持域语义。
