## ADDED Requirements

### Requirement: 主系统原生平台页与嵌入态子应用保持连续的壳层阅读节奏
主应用 SHALL 在统一宿主壳层中同时承托原生平台页与嵌入态子应用时，保持连续的视觉阅读节奏。用户从 `/platform/**` 切换到 `/oa/**` 或 `/scrm/**` 时，顶部标题区、侧边导航和原生页的结构化组件反馈 MUST 维持宿主级连续性，而不是让原生平台页看起来像独立于统一工作台之外的另一套产品。

#### Scenario: 从平台治理页切换到子应用页时宿主观感连续
- **WHEN** 用户从主系统平台治理页切换到宿主承载的 OA 或 SCRM 页面
- **THEN** 主系统侧边导航、顶部标题区与内容容器保持连续的门户节奏，用户不会因为原生页签、卡片或表格反馈突变而感到主系统和子系统是彼此割裂的两套后台

#### Scenario: 原生平台页在宿主内保持统一工作台身份
- **WHEN** 用户进入 `/platform/organization/departments`、`/platform/organization/employees` 或其他主系统原生页面
- **THEN** 页面通过与宿主壳层一致的结构节奏和主题覆盖持续表达“统一工作台中的平台治理域”身份，而不是呈现成与宿主导航脱节的独立页面皮肤

### Requirement: 宿主与子应用的样式边界在切换过程中保持稳定
主应用 SHALL 在承载 `oa-web` 与 `scrm-web` 时保持稳定的样式边界。宿主原生页面样式、OA 样式与 SCRM 样式 MUST 在各自生效范围内独立运作，用户来回切换业务域时不得因为遗留样式或全局覆盖顺序变化而看到宿主或子应用样式错位。

#### Scenario: 宿主切回原生平台页后维持自己的组件样式
- **WHEN** 用户从 `/oa/**` 或 `/scrm/**` 页面返回 `/platform/**` 页面
- **THEN** 宿主原生页面仍然呈现主系统定义的组件样式和宿主主题，不会因为子应用卸载后的样式残留而发生 tab、按钮、输入框或表格反馈变化

#### Scenario: 宿主切换业务域时当前子应用只呈现自身主题
- **WHEN** 用户在主系统内从 OA 页面切换到 SCRM 页面，或从 SCRM 页面切换到 OA 页面
- **THEN** 当前业务域只呈现自身主题与组件皮肤，不会出现另一个子应用遗留样式继续影响当前页面的情况
