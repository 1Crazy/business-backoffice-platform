## ADDED Requirements

### Requirement: 主系统原生页面复用共享后台组件结构语言
系统 SHALL 让 `main-web` 的原生平台页面复用与 `oa-web`、`scrm-web` 一致的后台组件结构语言。`el-tabs`、表格、按钮、输入框、分页、空态与卡片层级 MUST 通过主系统的语义化视觉令牌与全局组件样式统一表达，而不是继续在单页内零散分叉出另一套结构反馈。

#### Scenario: 主系统页签与子系统页签保持同构反馈
- **WHEN** 用户在主系统平台治理页与子系统的 tab 页面之间切换对比
- **THEN** 页签容器、圆角、激活态、间距和层级反馈保持同一套结构节奏，只允许颜色和宿主主题存在适度差异

#### Scenario: 主系统基础表面组件与子系统保持同一节奏
- **WHEN** 主系统原生页面渲染表格、表单、分页、空态或卡片容器
- **THEN** 这些基础表面组件沿用与子系统一致的边框、阴影、焦点态、悬停反馈和信息密度规则，而不是长成独立的第三套后台样式

### Requirement: 主系统宿主主题覆盖表达稳定统一门户身份
系统 SHALL 允许 `main-web` 在共享后台视觉语言之上提供更稳定克制的宿主主题覆盖。桌面侧边栏、顶部标题区、用户上下文区与移动端菜单抽屉 MUST 使用统一的宿主色板与层级关系，在表达“统一门户”身份的同时保持高对比度和后台可读性，不得因为宿主配色过亮、过重或过饱和而削弱长期使用的稳定感。

#### Scenario: 桌面端宿主壳层保持中性门户主题
- **WHEN** 用户在桌面宽度访问主系统任意 `/platform/**`、`/oa/**` 或 `/scrm/**` 页面
- **THEN** 主系统侧边栏与顶部标题区使用一致的中性宿主主题，既不会看起来像 OA 主题的复制，也不会误读成 SCRM 的经营子域界面

#### Scenario: 移动端菜单延续宿主主题而不跳脱
- **WHEN** 用户在平板或窄屏宽度打开主系统移动端菜单
- **THEN** 菜单抽屉延续与桌面端一致的宿主主题、文字对比度和当前页高亮逻辑，不会因为切到移动断点就回退为另一套不相关的视觉风格

### Requirement: 多后台应用的全局组件皮肤不得跨应用边界串扰
系统 SHALL 约束 `main-web`、`oa-web` 与 `scrm-web` 的全局组件皮肤作用域。任一应用对 `Element Plus` 基础结构的视觉覆盖 MUST 限制在自身宿主语境内，不得在用户切换平台原生页、OA 与 SCRM 时继续污染其他应用的 tab、按钮、表格、输入框或卡片样式。

#### Scenario: 子应用切换后不会污染主系统原生页签
- **WHEN** 用户在主系统内访问 OA 或 SCRM 页面后再返回 `main-web` 原生平台页
- **THEN** 主系统原生页签、按钮、表格和卡片继续使用主系统定义的视觉结构，不会被子应用遗留的全局组件样式覆盖

#### Scenario: 一个子应用不会覆盖另一个子应用的组件皮肤
- **WHEN** 用户在主系统内从 OA 页面切换到 SCRM 页面，或从 SCRM 页面切换到 OA 页面
- **THEN** 当前子应用只呈现自身主题下的组件皮肤，不会继承另一个子应用遗留的 tab、按钮、表格或输入框样式
