## Context

第三阶段的前提是：产品已经具备单企业落地价值，并且通过第二阶段获得了较强的流程配置、权限治理和企业交付能力。此时最大的产品瓶颈会从“能不能满足这家公司”转向“能不能复制给更多公司”。当前系统的核心数据模型、认证体系和治理语义仍然默认服务于单企业内部环境，因此平台化和 SaaS 化需要一次明确的租户边界设计。

第三阶段不仅是加几个新模块，而是为整套系统建立新的运行平面：平台运营平面负责租户开通、停用、监控和能力供给；租户管理平面负责每家企业内部的组织、权限、流程和配置治理；开放平台平面负责 API、Webhook 与外部身份和业务系统对接。

## Goals / Non-Goals

**Goals:**
- 为身份、组织、权限、业务数据、审计和配置建立统一租户边界。
- 提供平台运营端用于租户开通、初始化、停用、配额和运行状态治理。
- 提供租户级产品配置中心，使菜单、字段、表单、主题和模板能够按租户定制。
- 提供开放平台能力，支持 API、Webhook 和企业身份源集成。

**Non-Goals:**
- 不在第三阶段处理复杂商业计费、财务结算或完整市场化销售流程。
- 不把所有产品差异都做成完全可视化低代码平台。
- 不一次性支持无限种外部系统集成，首批聚焦统一身份和关键业务对接。

## Decisions

### Decision: 采用“全局平台 + 租户工作区”双平面模型，而不是继续在单平面里叠加租户字段

第三阶段会显式区分平台运营者与租户管理员。平台运营者负责租户生命周期、模板供给和平台级监控；租户管理员负责本租户内部的组织、员工、角色、流程和业务配置。主应用需要能根据当前登录身份进入平台运营视角或租户内部视角。

选择双平面模型，而不是简单给现有页面补一个 `tenantId` 过滤，是因为平台运营者和租户管理员看到的对象与权限语义本质不同。分平面更容易控制权限边界，也能避免平台操作误入租户业务上下文。

### Decision: 租户隔离采用“显式租户键 + 仓储层强制约束 + 会话绑定”组合方案

核心身份对象、业务对象、配置对象和审计对象都需要显式具备租户归属，并在仓储层和鉴权层强制应用租户过滤。登录会话、刷新会话和 API 凭证也必须绑定租户上下文，避免跨租户复用。

选择显式租户键组合方案，而不是依赖约定式过滤，是为了降低数据串租风险。显式租户模型也能为后续分区、归档和平台级运维提供更清晰的基础。

### Decision: 产品配置采用“平台默认值 + 租户覆盖 + 业务域覆盖”的分层继承模型

菜单、字段、表单、主题、模板和行业配置都会遵循分层继承模型：平台提供默认值，租户可以覆盖，必要时业务域再做局部补充。运行时读取配置时，系统按从局部到全局的顺序解析生效值。

选择分层继承，而不是每个租户从零配置所有内容，是为了兼顾标准化产品交付和租户差异化能力。平台运营端可以沉淀行业模板，租户端只需做有限调整。

### Decision: 开放平台先聚焦“身份接入 + 数据接入 + 事件回调”三类能力

开放平台第一批能力聚焦三件事：让外部系统可以通过 Open API 读写受控数据；让外部系统可以通过 Webhook 接收关键事件；让企业可以通过 SSO、LDAP 或 OAuth 等方式接入统一身份源。所有 API 凭证、Webhook 订阅和身份连接器都必须是租户级对象。

选择这三类能力作为第一批，是因为它们最直接影响 SaaS 平台能否进入企业现有 IT 环境，而无需一开始就建设过宽的集成市场。

## Risks / Trade-offs

- [多租户改造触及核心模型，迁移风险高] → 采用单企业默认租户回填策略，先完成核心模型与会话的租户化，再逐步扩展到所有业务模块。
- [平台运营端和租户端职责混淆] → 在导航、权限、路由和会话语义上明确区分平台平面与租户平面。
- [租户配置继承关系复杂，运行时难以解释] → 保持清晰的默认值、覆盖值和最终生效值展示，并在配置中心提供来源说明。
- [开放平台能力扩大安全面] → 所有 API、Webhook 和身份接入都必须绑定租户、权限、审计和密钥轮换能力。

## Migration Plan

- 先引入默认租户与租户基础表结构，把现有单企业数据回填到默认租户。
- 逐步为身份、组织、权限、业务数据、配置和审计对象增加租户归属，并在仓储层强制应用租户过滤。
- 引入平台运营端导航和权限体系，再逐步把租户开通、模板供给和运行状态治理迁入该平面。
- 在租户隔离稳定后再开放 API 凭证、Webhook 和企业身份接入。

## Open Questions

- 平台运营端与租户内部端是否共用一套主应用壳层，还是采用独立壳层与域名。
- 多租户首版是否要求数据库物理隔离，还是逻辑隔离即可满足目标客户。
- 行业模板和租户覆盖的冲突处理，是否需要显式发布版本与回滚机制。
